## 6. C — exact legacy RPC, callers, and privilege design

The function is `public.record_cpsc_identity_observation(text,text,text,text,text,date,text,timestamptz,text)`. Local and production owner is `postgres`; it is `SECURITY DEFINER` with `search_path = ''`. Before C, direct EXECUTE is true for `service_role` and owner, false for `anon` and `authenticated`. The function itself checks `private.cpsc_is_worker()`. The catalog shows zero `pg_depend` references to this function; PL/pgSQL body calls still exist and were audited by source search.

No deployed Edge entry point directly invokes the nine-argument RPC. The live child uses `public.record_cpsc_retained_observation(...,jsonb)`, which calls the nine-argument gate inside a `postgres`-owned `SECURITY DEFINER` function after payload/hash verification. `private.cpsc_backfill_apply(uuid,jsonb,text,integer)`, also `postgres`-owned and `SECURITY DEFINER` with empty search path, calls it twice: once for stored historical notices and once for frozen captured-current observations. `private.cpsc_historical_backfill(jsonb,text,boolean,text,integer)` calls that backfill helper. The helper temporarily sets a service-role claim for the gate and restores it. Nested execution therefore uses the definer's function privileges while the gate's worker predicate sees the intended claim.

Direct references also occur in Phase 16.10/11/12/16.16 migration history, Phase 16.10/11/12/16.16 and remote pgTAP fixtures, the Phase 16.12/13 backfill rehearsal scripts, Phase 16.10/11 simulations, Phase 16.16A rollback-validation builder, and Phase 16.11/12/13 HTTP-auth smoke scripts. The old HTTP smoke scripts intentionally exercise the former direct worker call and will need versioned updates if reused after C; they are not deployed callers. No historical migration, manifest, fixture payload, or evidence was rewritten.

The [forward-only migration](../supabase/migrations/20260927190041_phase_16_20_restrict_legacy_cpsc_observation_rpc.sql) has SHA-256 `c7329a6b652cbf6a7bcd62d5c9d3aeae3b2516003c59f2c41ad6f586d0997136`. Rollback would require an explicit `GRANT EXECUTE ... TO service_role`, restoring the old direct worker surface. The design assumes the already-applied Phase 16.11 public/anon/authenticated revokes and the owner/definer relationships remain in place.
