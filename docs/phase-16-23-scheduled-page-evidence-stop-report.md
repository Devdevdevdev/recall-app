## 3. Atomicity defect and 4. commit design

Previously the Edge module could commit a semantic revision before `record_cpsc_page_fetch` rejected a final URL. That could leave a revision and stale prior reviews without a successful fetch. `commit_cpsc_page_evidence(claim_id, snapshot, revision, candidates, ledger)` now checks the active lease, reconciled identity, requested canonical URL, final URL, 200 status, HTML type, normalized recall number and URL, payload bounds, and candidate array before invoking the existing validated RPCs inside one Postgres transaction. The existing RPCs still validate hashes, timestamps, redirects, revision binding, proposal scope/address and coverage. Any later fetch or ledger error rolls back the revision, staleness trigger, fetch, candidates and ledger together. pgTAP verifies rejection before a write and rollback after both late fetch and late ledger validation.

This boundary trusts the worker for byte-hash and semantic-hash calculation because the database receives hashes and normalized evidence, not the source bytes. The legacy direct service-role RPC sequence remains callable for historical compatibility. It is **not** an atomicity guarantee for callers outside the new worker. This is a deployment gate to resolve before scheduling the stage.

## 5. Durable attempts and 6. claim/retry design

`cpsc_page_work_state` stores one row per identity: claim ID/expiry, next attempt, total attempt count, consecutive failures, last attempt/success and last outcome. `cpsc_page_attempts` retains claimed and completed outcomes with time, HTTP status, final URL, byte hash, bounded error code, revision/fetch links. Outcomes are `claimed`, `fetched_unchanged`, `fetched_changed`, `unresolved_structure`, `identity_redirect`, `temporary_failure`, `permanent_unsupported`, and `budget_deferred`.

The claim RPC selects reconciled canonical identities by due time, then oldest success/attempt time and recall number; it takes identity row locks with `SKIP LOCKED`, limits batches to ten, and uses a unique partial index for one active claimed attempt per identity. Claims expire after 30 seconds. A later claim closes an expired attempt and recovers the identity. Temporary failures back off at 5 minutes × 2^(consecutive failures − 1), capped at 24 hours. Unresolved parser scope retries after seven days; identity redirects and unsupported pages after 30 days; success refreshes after one day. Budget deferral retries after one minute without incrementing failure count. A two-session local race produced one claim and zero duplicate claims.

## 7. Bounds and 12. worker architecture

`process-cpsc-page-evidence` is a separate Edge Function, with no invocation from current ingestion, matcher, push, automation or cron. The input accepts only `dryRun`, `maxPages` (1–10), and `timeBudgetMs` (1–20,000). Dry run claims nothing. The worker claims one target at a time, allows at most two in-flight pages, and stops making claims at its 20-second budget. A late claim is durably marked `budget_deferred`. Each fetch has its own deadline up to 10 seconds. The RPC commit is atomic; no partial semantic evidence is written if it fails. The current implementation waits for already-started work, so a stalled database RPC could make total response time exceed 20 seconds. A hard end-to-end wall-clock cap needs cancellation/statement-timeout support before activation.

## 8. Fetch security and 9. DNS/SSRF assumptions

The existing fetcher requires literal HTTPS `cpsc.gov` or `www.cpsc.gov`, path `/Recalls/`, no userinfo or port, manual redirects with each hop revalidated, at most three redirects, HTML content type, at most 1 MB streamed bytes, fatal UTF-8 decoding and a 10-second transport/body deadline. The worker rejects a final URL different from the claimed canonical URL and a page naming another recall before it can submit semantic evidence. It does not accept arbitrary URLs from HTTP callers. TLS validation and the fetcher's host/path checks are the actual guarantees. Deno resolves DNS inside `fetch`; the code cannot pin the resolved address, so a separate DNS pre-check would not prevent rebinding. The residual assumption is that the platform's resolver and TLS validation remain trustworthy for the allowed CPSC hostnames.

## 10. Raw evidence decision

Independent replay of HTML extraction **does require raw source bytes**. This phase records the SHA-256 byte hash and normalized, section, table, proposal and coverage evidence, but not the raw HTML. Before a shadow run intended to support independent replay, add a private append-only payload store keyed by identity and hash: maximum 1 MB per payload; DB recomputes SHA-256 over bytes; only the canonical CPSC `/Recalls/` claim can create it; no arbitrary URL or consumer/user data; no `anon`, `authenticated` or direct `service_role` table grant; explicit retention limit and audited deletion policy. Link the payload to the successful fetch in the same atomic commit. This is a concrete remaining prerequisite, not an implicit unlimited HTML store.

## 11. Semantic revisions and 12. coverage

The existing normalizer hashes safety-relevant structured content; whitespace, DOM attributes and cosmetic markup do not make a new semantic revision. Model, date-code, title, scope wording or table-row changes do. Raw-byte hashes belong to fetch attempts. The parser/census emits a five-way disposition for each consumed description sentence/table row/region: `parsed_reviewable`, `parsed_deferred`, `unresolved`, `unsupported`, or `ignored_non_safety`. DB coverage validation binds every stored table row and reviewable relation to the revision/candidates, recomputes completeness/fingerprints, and refuses missing or contradictory ledgers. It cannot independently recover an omitted prose sentence from a missing raw HTML payload; the worker's independent DOM census is the current completeness boundary.

## 13. Review/identity roles and 14. failure semantics

Candidates are inserted with the table default and check constraint `status='unreviewed'`. The worker code calls no review, reconciliation, matcher, alert, push or v2 activation RPC. pgTAP confirms the service role lacks human review and reconciliation execute grants. Wrong final URL/recall yields `identity_redirect`, with no alias, review or revision. Timeout, 5xx, 429 and network errors yield `temporary_failure`, with no revision and capped backoff. Non-HTML, oversize, invalid UTF-8 and unsupported extraction yield `permanent_unsupported`; parser scope ambiguity yields `unresolved_structure`. These outcomes do not affect canonical API ingestion or v1 watermarks.

The service role is shared with the existing v1 system, so it is not globally limited to these three page RPCs. A separate page-specific role or narrower credential would be required for that stronger property.
