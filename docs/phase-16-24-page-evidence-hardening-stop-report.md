## 3. Gate A: legacy RPC analysis

The bypass was `pageIngestion.ts` calling `public.record_cpsc_page_revision(uuid,text,jsonb,jsonb,jsonb,text)`, `public.record_cpsc_page_fetch(uuid,uuid,timestamptz,integer,text,text,text,text,text,jsonb,text)`, `public.propose_cpsc_candidate_criterion(uuid,uuid,jsonb,text,text,jsonb,text,text,text)`, and `public.record_cpsc_page_coverage(uuid,jsonb)` in separate transactions. `public.get_cpsc_page_fetch_targets(integer)` exposed the old target path. Each RPC is owned by `postgres`, is `SECURITY DEFINER`, and sets an empty `search_path`. Before 16.24, the direct page RPCs had `service_role` EXECUTE. The sequence can leave a revision behind when a later fetch or ledger fails. Historical owner-run backfill and pgTAP fixtures use these functions; local legacy HTTP/test callers use `pageIngestion.ts`. Inspection of all seven deployed pre-installation Edge Function file sets found **zero imports or calls** to the direct page path. The same deployed bundles were checked again after installation.

## 4. Gate A: final privileges

The five old direct page functions above and the old `commit_cpsc_page_evidence(uuid,jsonb,jsonb,jsonb,jsonb)` are denied to `service_role`, `anon`, `authenticated`, and `cpsc_page_worker`. Owner `postgres` retains historical execution. Production ACL queries confirmed those results and an empty `search_path`. The new worker calls only claim, finish, and `commit_cpsc_page_evidence_verified`; it has no direct legacy evidence grant. Wrong final URL, tampered bytes, and late invalid coverage leave no partial semantic revision, successful fetch, candidate, coverage ledger, or raw payload in local rollback tests.

## 5. Gate B: raw-evidence architecture

`private.cpsc_page_raw_payloads` stores exact fetched `bytea` keyed by lowercase SHA-256, with a generated byte length and first-retained timestamp. It admits 1–1,000,000 bytes and verifies the SHA-256 in Postgres. A nullable `raw_payload_sha256` foreign key on `private.cpsc_page_attempts` links successful attempts to the payload; that attempt already links the fetch and semantic revision. The fetch retains final/canonical URL, content type, and retrieval time. No cookies, request headers, credentials, or user data are stored. The Edge HTTP caller cannot supply a URL or HTML body; bytes come from the existing HTTPS CPSC `/Recalls/` fetcher after host, redirect, type, size, UTF-8, final URL, and recall-identity checks. The database trusts that dedicated fetcher for network provenance; it independently verifies bytes and hash.

## 6. Gate B: immutability, hash, and replay

Raw rows have RLS with no policy and no direct worker-role table grants. Triggers reject UPDATE, DELETE, and TRUNCATE; the attempt foreign key uses `ON DELETE RESTRICT`. The verified commit inserts or reuses bytes inside the semantic transaction. Local pgTAP rejects tampered bytes and confirms rollback after a late ledger error. A local Char-Broil fixture run retained **84,846 exact bytes**; worker SHA-256, database SHA-256, and payload key agreed. Independent replay from the stored bytes through the parser reproduced the stored semantic hash and coverage ledger without CPSC network access. Identical bytes reused one payload; different cosmetic bytes created a second payload while keeping the semantic revision. No pruning was added. The 27 pre-16.24 historical revisions still lack raw bytes and remain a replay limitation.

## 7. Gate C: timeout contract

The 20-second setting is an **admission budget**, not a hard HTTP wall-clock guarantee. The worker stops new claims when fewer than 18 seconds remain and defers a claimed page if fewer than 16 seconds remain. This reserves for the 10-second fetch, up to four seconds of database statement work, parsing/serialization, and cleanup. The dedicated login has role-level `statement_timeout=4s`, `lock_timeout=3s`, and `idle_in_transaction_session_timeout=5s`; Postgres enforces cancellation of in-flight statements. The Postgres client uses a two-second connection timeout and a bounded close. These settings do not alter `service_role` or unrelated v1 operations. A slow fetch and slow DB statement have finite operation limits; Edge scheduling and parser CPU mean a strict 20-second total HTTP response has **not** been claimed or proved.

## 8. Gate C: deliberately slow DB proof

A real connection as `cpsc_page_worker` ran a local security-definer probe that updated a claimed attempt, inserted raw bytes, then slept six seconds. Postgres canceled it with SQLSTATE `57014` after **4.05 seconds**. The insert and attempt update rolled back. After the 30-second lease was made expired in the local fixture, a second claim recovered the identity and closed the old attempt as `temporary_failure`. The old credential failed to connect after its local password was revoked. Existing fetch tests cover abort-ignoring transports, stalled bodies, 10-second deadline behavior, oversized bodies, and invalid UTF-8.

## 9. Gate D: least-privilege capability

It connects directly to Postgres with the pinned `postgres@3.4.7` driver and does not read `SUPABASE_SERVICE_ROLE_KEY` or `SUPABASE_SECRET_KEYS`. Its only executable public `SECURITY DEFINER` functions are `claim_cpsc_page_evidence`, `finish_cpsc_page_attempt`, and `commit_cpsc_page_evidence_verified`.
