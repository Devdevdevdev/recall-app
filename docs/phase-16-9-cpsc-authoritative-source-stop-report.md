**Canonical key:** `(source_id for authoritative cpsc, official_recall_number)`, corroborated by a normalized `https://www.cpsc.gov/Recalls/...` page URL and publication date/title. Internal `recall_notices.id` remains stable and unchanged. Resolve a new API record by recall number and canonical URL; if either points to a different known identity, quarantine the observation. A changed numeric API ID is recorded as an alias observation, never used alone for upsert. URL normalization permits `cpsc.gov` → `www.cpsc.gov`, removes query/fragment and trailing slash, and preserves path spelling and percent encoding. A redirect to a different path needs explicit URL alias review.

The additive schema has seven private tables: `cpsc_source_identities`, `cpsc_source_aliases`, `cpsc_api_revisions`, `cpsc_page_revisions`, `cpsc_page_fetches`, `cpsc_candidate_criteria`, and `cpsc_candidate_review_ledger`. Aliases preserve upstream ID/URL, provenance, notice association, and first/last seen times. API ID aliases are indexed but deliberately **not globally unique**. API revisions retain payload hashes and observation windows; page revisions key one semantic hash to an identity, while fetches record separate HTTP observations and raw byte hashes. No primary production identity is rewritten.

## B. Authoritative page evidence

The local parser accepts only official HTTPS CPSC recall URLs. It records the canonical URL, captured fetch timestamp, HTTP status, raw SHA-256, title, displayed recall number and date, normalized text for the labeled Recall Details sections, every description table with headers and cells, section hashes, and a semantic revision hash. It verifies the page's displayed recall number/date against the stored record and the raw hash against Phase 16.8. It stores relevant text/cells and **no arbitrary HTML or tracking markup**. Source address components are source, recall number, canonical URL, semantic revision hash, `recall-details/description`, table-header hash, row key, and normalized excerpt fingerprint. No character offset is required.

Normalization uses Unicode NFC and collapses whitespace including nonbreaking spaces. It preserves case, punctuation, cell values, column order, row order, and table row associations. It expands explicit HTML `rowspan` associations without inventing blank cells. The raw hash detects transport/markup changes; the evidence hash covers official identity, title, date, normalized description, and structured tables. A raw hash change with the same evidence hash is a transport/cosmetic observation, not a new semantic revision. Changing any retained evidence creates a new revision for comparison; that does **not** automatically approve or match anything. Image-only evidence remains unresolved.

## Review and stale rules

The candidate store is fixed to `unreviewed`; it has no path to matching. A future restricted admin workflow may append a `reviewed` or `rejected` ledger decision. `reviewed` requires an authenticated human reviewer, explicit attestation, accepted scope ID, source revision hash, and evidence address. Historical scope UUIDs are retained as audit values without a foreign key that would block routine scope replacement; refresh must mark affected approvals stale. `rejected` remains auditable and unusable. A later material change appends `stale`; stale is unusable until a new human review. Codex or a future model is never the human reviewer. Any edited semantics require a new candidate and review, not mutation of a prior attestation.

The review UI contract must display the official CPSC URL, official recall number, current revision and fetch time, exact description paragraph/table row and headers, verbatim short authoritative excerpt, normalized criterion type/operator/value, mandatory versus descriptive interpretation, all conjunction members, proposed scope, and source fingerprint. Accept/reject controls must be unavailable until the evidence and every required conjunct are visible. The UI and approval endpoint are **design only** in this gate; the migration grants no client or ingestion-worker right to insert review decisions.

On refresh: (1) if raw bytes differ but normalized evidence hash is identical, record a fetch only; approval stays current. (2) If semantic revision changes, compare every approved address and its dependency group. A changed/missing identifier, operator, list completeness, conjunction membership, scope association, header/row identity, official recall number, canonical URL, title/date identity, or addressed excerpt fingerprint makes the prior decision stale. A row that moved but retains a key needs explicit readdressing; do not use offsets. (3) If only an unrelated normalized section changed, record a deterministic equivalence check for the unchanged addressed evidence and full dependency group; retain the original locked review revision plus that equivalence record. If equivalence cannot be proved, stale. This revalidation executor is a Phase 16.10 design task, not a running process here.
